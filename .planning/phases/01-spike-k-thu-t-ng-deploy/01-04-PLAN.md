## Phase Goal

**As a** solo operator play-testing on my two reference phones, **I want to** open https://game.doibung.com, walk a low-poly office, slap NPCs into ragdolls and smash 20+ objects in a build that any commit can deploy with one command, **so that** I have measured proof that Three.js + Rapier meets the size, fps and iOS-stability budget before any gameplay phase builds on it.

<objective>
Walking-skeleton slice 2 (server side, authoring only): idempotent, backed-up, verifiable tooling that wires the game into doibung's Caddy on the VPS, a drift check every deploy runs, and an approval-token lock that makes the server change impossible without a token the operator types. This plan runs the check, the preflight and the token refusals against the real server as live negative controls, but never changes doibung's files or containers; the change happens in plan 01-12.

Purpose: the Caddy recreate is the only step that can interrupt doibung.com, so the tooling itself (not a checklist line) must refuse to act without operator approval, and must make a wrong compose file, a lost cert or a silent whattoeat overwrite impossible to miss.
Output: Node orchestration (`scripts/infra.mjs`, `scripts/lib/*`), three bash scripts sent over stdin, HANDOFF note, unit tests with negative controls.
</objective>
