## Approval rule (applies to Tasks 2 and 3)

- The only valid approval is a reply from the operator that contains a string matching `APPROVE-CADDY-[0-9a-f]{8}`. The executor copies that substring exactly into `--approve=`.
- The executor must never build a token from `APPROVAL_CODE=` output, from 01-GO-LIVE.md, or from any file. Writing a line into a file is not approval.
- A reply that is "reject", empty, ambiguous, or has no well-formed token means STOP: add a STATE.md blocker and end the plan.
- If `infra:apply` answers APPROVAL_TOKEN_INVALID (state changed or nonce expired/consumed), stop and re-present Task 2 with the fresh preflight; never retry with a modified token.
